# Ambit microprograms

gem5-CIMD executes every CIM instruction as a sequence of Ambit AP/AAP DRAM
commands read from this directory: `<op><bitwidth>.txt`, loaded by
`DRAMInterface::executeAmbitMicroprogram()` in `src/mem/dram_interface.cc`.
Supported bitwidths are 4, 8, 16, 32 and 64.

The microprograms only determine the **timing** of an operation (which and how
many AP/AAP commands are issued). The functional result of a RowOp is computed
separately in `AbstractMemory::access()` (`src/mem/abstract_mem.cc`).

| Instruction | File prefix | Result (bits LSB first, `n` = bitwidth) |
|---|---|---|
| `rowand`, `rowor`, `rowxor`, `rownot` | `and`, `or`, `xor`, `not` | bitwise; hand-written, independent of `n` |
| `rowadd`, `rowsub` | `add`, `sub` | `a + b`, `a - b` (mod 2^n) |
| `rowmult` | `mul` | `a * b` (2n bits) |
| `rowdiv` | `div` | `a / b` (unsigned) |
| `rowmin`, `rowmax` | `min`, `max` | unsigned min / max |
| `rowequal`, `rowgreater`, `rowgreater_equal` | `eq`, `gt`, `ge` | 1 bit, unsigned compare |
| `rowif_else` | `ifelse` | per bit: `mask ? a : b` |
| `rowabs` | `abs` | two's-complement absolute value |
| `rowbitcount` | `bitcount` | population count (⌈log2(n+1)⌉ bits) |

## Where they come from

All microprograms except the four bitwise ones are generated by
[LIME](https://github.com/kusnezoff-alexander/lime) (commit `27c4086`), an
e-graph based compiler from majority-inverter graphs to Ambit AP/AAP programs.

To (re)generate a microprogram, build LIME's `lime_ambit_benchmark` (see its
README) and run it on the network key, e.g. `div16`:

```sh
AMBIT_REWRITE=0 ./lime_ambit_benchmark div16 > div16.log   # 0: no e-graph rewriting
awk '/^== Program/{p=1;next} /^== /{p=0} p' div16.log | grep -E '^AA?P' > div16.txt
```

Copy the resulting file here; gem5 picks it up at runtime, no rebuild needed.

## Format

One command per line:

- `AAP <src> <dst>`: copy `src` to `dst` (activate-activate-precharge).
  A three-row `src` group is a triple-row activation whose majority is copied.
- `AP [x, y, z]`: triple-row activation; all three rows become `MAJ(x, y, z)`.

Rows: `I<k>` inputs, `O<k>` outputs, `S<k>` scratch rows, `T0`-`T3` compute
rows, `DCC0`/`DCC1` dual-contact cells (`~DCCx` reads/writes the negation),
`C0`/`C1` constant rows. Inputs are laid out operand after operand, LSB first:
`a` on `I0..I(n-1)`, `b` on `I(n)..I(2n-1)` (for `ifelse`: mask, `a`, `b`).
gem5 accepts exactly the row groups listed in `parseBracketGroup()`.

## Verification

`verify.py` simulates a microprogram bit-parallel on random inputs, checks the
outputs against the operation above, and checks that gem5 can parse every row
group:

```sh
./verify.py ge 32 ge32.txt
```
